# 运维手册

## 1. 服务组成

| 服务 | 作用 | 生命周期 |
|---|---|---|
| `setup` | 安装 Python 依赖、下载权重、校验模型 | 一次性，退出码 0 表示成功 |
| `app` | FastAPI + 静态前端（端口 8001） | 常驻，`restart: unless-stopped` |

依赖安装在 Docker 卷 `ultraconsole_ultra-envs`，pip 缓存在 `ultraconsole_ultra-pip`；镜像升级不会重建它们，除非 requirements 变化（`setup` 会检测哈希并重建）。

## 2. 常用命令

在交付目录执行（Windows 的 PowerShell / 命令提示符均可）：

```bat
docker compose ps
docker compose logs --tail 200
docker compose logs -f app
docker compose restart app
docker compose down
docker compose up -d
docker compose run -T --rm setup
```

## 3. 备份

需要备份的只有两个目录：

| 目录 | 内容 | 建议频率 |
|---|---|---|
| `data\vlm` | 上传视频、分析记录、证据图 | 每日/每周 |
| `models` | 模型权重（可重新下载） | 一次即可 |

```powershell
Compress-Archive -Path .\data -DestinationPath "D:\backup\ultraconsole-data-$(Get-Date -Format yyyyMMdd).zip"
```

恢复时先 `停止.bat`，解压覆盖 `data\`，再 `启动.bat`。

## 4. 升级与回滚

升级：

1. 新镜像 tar 放入 `images\`；
2. `更新.bat`（会自动把 `.env` 的 `ULTRACONSOLE_TAG` 切到新版本）；
3. 观察日志：`docker compose logs -f app`。

回滚：

1. `停止.bat`；
2. 删除/移走 `images\` 里的新 tar，放回旧 tar；
3. 重新 `更新.bat`。

若新版本修改了依赖，`setup` 会重建 `ultra-envs`；旧镜像回滚时会再次重建，属正常现象。

## 5. 资源限制

Docker Desktop 的 WSL 2 默认最多使用约 50% 内存。若宿主机内存紧张或需要跑 4B 模型，在 `%UserProfile%\.wslconfig` 中配置：

```ini
[wsl2]
memory=12GB
processors=8
swap=8GB
```

保存后执行 `wsl --shutdown`，再重启 Docker Desktop。

## 6. 日志与诊断

| 文件/命令 | 内容 |
|---|---|
| `docker compose logs app` | 后端、模型加载、分析任务日志 |
| `data\vlm\runs\<run_id>\*.log` | 单次分析的 tracking / cues / understanding 日志 |
| `诊断.bat` | Docker、GPU、镜像、容器、健康检查汇总 |

分析任务卡住时，优先看 `data\vlm\runs\<run_id>\status.json` 与对应阶段的 `.log`。

## 7. 鉴权

默认不启用。启用需要两步且必须一致：

1. 构建镜像时注入前端 token：
   ```bash
   docker build --build-arg VITE_ULTRA_API_TOKEN=<token> ...
   ```
2. 在 `.env` 中设置：
   ```ini
   ULTRA_API_TOKEN=<token>
   ```

两者不一致会导致页面请求 401。

## 8. 数据与隐私

- 视频、截图、分析结果全部在本机 `data\`，不上传云端。
- `models\` 只含公开模型权重。
- 交付包不含任何业务视频；示例数据请勿随包分发。

## 9. 卸载

```bat
停止.bat
docker compose down -v      # 同时删除依赖卷；data/models 仍保留
```

然后删除交付目录。`data\` 建议先备份。
