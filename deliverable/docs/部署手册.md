# 部署手册（Windows 11）

本系统以 Docker 镜像交付，运行在 Windows 11 的 Docker Desktop 上。使用方不需要 Linux、Python 或 Node 经验。

## 1. 前置条件

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 11 64 位（家庭版/专业版） |
| 显卡 | NVIDIA，建议 RTX 3060 12G 及以上 |
| 驱动 | Windows 版 NVIDIA 驱动（支持 WSL 2 的版本即可） |
| Docker | Docker Desktop for Windows（WSL 2 backend；大企业需订阅授权） |
| 内存 | 建议 ≥ 16GB |
| 磁盘 | ≥ 30GB 可用空间（依赖 6–8GB + 权重 4.5GB + 数据） |
| 虚拟化 | BIOS 中开启 CPU 虚拟化（多数机器默认开启） |

> Docker Desktop 对大型企业需要付费订阅。部署前请先确认单位授权情况。

## 2. 安装

### 2.1 显卡驱动

到 [nvidia.cn](https://www.nvidia.cn/Download/index.aspx) 下载对应型号的 Windows 驱动，按提示安装。安装完成后打开命令提示符执行：

```bat
nvidia-smi
```

能看到显卡型号、驱动版本即成功。

### 2.2 Docker Desktop

1. 下载并安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)。
2. 安装时保持默认的 **WSL 2 backend**。
3. 启动 Docker Desktop，等待左下角显示 **Engine running**。

第一次启动 Docker Desktop 会自动准备 WSL 2 环境，不需要手动执行任何 Linux 命令。

### 2.3 解压交付包

建议解压到固定目录，例如：

```
D:\UltraConsole
├── 启动.bat
├── 停止.bat
├── 更新.bat
├── docker-compose.yml
├── .env
├── images\
├── models\
├── data\
└── offline\
```

路径尽量不含空格；中文路径一般可用，但英文短路径更稳妥。
`images`、`models`、`data`、`offline` 若解压后不存在，启动脚本会自动创建。

## 3. 首次启动

双击 **启动.bat**。启动器会自动：

1. 检查 Docker 是否运行，必要时启动 Docker Desktop；
2. 检查 NVIDIA GPU；
3. 如果本机没有镜像，从 `images\*.tar.gz` 导入；
4. 运行 `setup`：从国内 PyPI 镜像安装 Python 依赖（约 6–8GB），并从 ModelScope 下载 Qwen 权重（约 4GB）；
5. 启动服务并等待健康检查；
6. 在浏览器打开 `http://localhost:8001`。

YOLO11 姿态权重（`models\detect\yolo11m-pose.pt`）已随交付包内置，不联网下载。
首次运行耗时取决于网速，期间窗口会持续输出进度，请不要关闭。之后再启动通常在 1 分钟内完成。

### 下载源

默认全部为大陆可直连地址，无需代理：

```ini
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
HF_ENDPOINT=https://hf-mirror.com
VLM_MODEL_SOURCE=modelscope
MODELSCOPE_ENDPOINT=https://modelscope.cn
```

如 ModelScope 下载失败，脚本会自动回退到 `hf-mirror`；也可手动把 `VLM_MODEL_SOURCE` 改成 `huggingface`。
需要换源时编辑 `.env` 后重新双击「启动.bat」。

### 端口冲突

修改 `.env`：

```ini
ULTRACONSOLE_PORT=8080
```

重新启动后访问 `http://localhost:8080`。

## 4. 日常操作

| 操作 | 方式 |
|---|---|
| 启动 | 双击 `启动.bat` |
| 停止 | 双击 `停止.bat`（数据保留） |
| 查看日志 | 双击 `查看日志.bat` |
| 环境诊断 | 双击 `诊断.bat` |
| 打开数据目录 | 双击 `打开数据目录.bat` |

数据目录结构：

```
data\
├── vlm\                 # 上传的视频、分析记录、证据截图
├── video-previews\      # 浏览器预览转码缓存
├── .hf\                 # HuggingFace 缓存
└── .ultralytics\        # YOLO 配置
models\
├── Qwen3-VL-2B-Instruct\
└── detect\yolo11m-pose.pt
```

## 5. 更新

1. 把新的 `ultraconsole-x.y.z.tar.gz` 放进 `images\`；
2. 双击 `更新.bat`；
3. 启动器导入新镜像、校验依赖、重启服务。

`data\` 与 `models\` 不会被删除；依赖只在 requirements 变化时重装。

## 6. 局域网访问

默认只映射到本机 `8001`。如需局域网访问：

1. 确认 Windows 防火墙允许该端口；
2. 在 `.env` 中设置端口；
3. 如对外提供服务，建议启用鉴权（需要重新构建镜像，见 `README.md` 的 token 说明）。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 提示 Docker 未运行 | 打开 Docker Desktop，等待 Engine running |
| 未检测到 `nvidia-smi` | 重装 NVIDIA 驱动并重启 |
| 页面能开但分析报 CUDA 错误 | 运行 `诊断.bat`；确认 Docker Desktop 的 WSL integration 已启用，重启 Docker Desktop |
| 首次下载卡住 | 检查到 `pypi.tuna.tsinghua.edu.cn` 与 `modelscope.cn` 的网络；也可切到 `mirrors.aliyun.com` 或 `hf-mirror` |
| Qwen 下载失败 | 默认 ModelScope；可在 `.env` 设 `VLM_MODEL_SOURCE=huggingface` 走 `hf-mirror` |
| 预览视频转码失败 | 该功能依赖 NVENC。先运行 `诊断.bat` 确认显卡支持；老显卡可能不支持 H.264 编码 |
| 端口被占用 | 修改 `.env` 的 `ULTRACONSOLE_PORT` |
| 更新后仍显示旧版本 | 确认 `images\` 里放的是新 tar，且 `更新.bat` 没有报错 |

## 8. 卸载

1. 双击 `停止.bat`；
2. Docker Desktop → Containers/Volumes，删除 `ultraconsole` 相关项；
3. 备份 `data\` 后删除整个目录。
